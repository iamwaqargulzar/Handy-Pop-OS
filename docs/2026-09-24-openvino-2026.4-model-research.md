# OpenVINO 2026.4 ASR model investigation

Date: 2026-09-24

## Release boundary

OpenVINO 2026.4 adds `Qwen3-ASR` and early `Fun-ASR-Nano-2512` support to
`ASRPipeline`, but Intel's release notes validate those additions on CPU/GPU,
not NPU. OpenVINO GenAI's ASR dispatcher currently implements only Whisper,
Qwen3-ASR, and Fun-ASR. Handy's Parakeet TDT path remains a custom fourth
architecture.

Handy must not list a model under the NPU filter merely because OpenVINO can
export it. A release entry requires a native worker load, an
`actual_device=NPU` result, and a correct transcription on the target Intel
NPU. No silent CPU/GPU speech inference is accepted.

## Added: Qwen3-ASR 0.6B

The official dynamic OpenVINO export fails direct NPU compilation. Handy's
static split pipeline solves the same constraints already addressed for the
1.7B model:

- fixed 100-frame speech-encoder chunks execute on NPU;
- official ASR-trained text weights are mapped without modification to the
  standard stateful Qwen3 causal-decoder contract;
- the NPUW decoder consumes `inputs_embeds`, `attention_mask`, and
  `position_ids` with a 1,024-token prompt bucket;
- CPU performs only feature extraction, tokenizer/detokenizer work,
  prompt/audio embedding assembly, and greedy token selection.

Both variants passed the 11-second JFK reference transcription:

| Variant | Published bytes | Warm load | Transcription | Result  |
| ------- | --------------: | --------: | ------------: | ------- |
| INT8    |   1,151,927,643 |   8.785 s |       1.097 s | Correct |
| INT4    |     883,954,227 |  13.338 s |       1.119 s | Correct |

The worker reported `actual_device=NPU` for both. INT8 is the quality-oriented
0.6B choice; INT4 is explicitly presented as a size/accuracy tradeoff. Models
are on-demand downloads and add no weights to the installer.

## Investigated, not listed yet

### Fun-ASR Nano 2512

The official INT8 export is about 823 MB. Direct NPU compilation fails because
both encoder and Qwen decoder retain multiple unbounded dimensions. Bounded
reshape experiments also fail inside the NPU compiler. Fun-ASR remains a good
future candidate because its decoder is Qwen3 0.6B, but it needs a dedicated
static feature/encoder contract and a split decoder built from Fun-ASR's own
weights. It must not reuse Qwen3-ASR weights.

### Parakeet TDT-CTC 110M

A third-party INT8 OpenVINO graph was examined only as a topology probe. After
fixing the acoustic input to `[1, 80, 1600]`, it compiled on NPU in 28.061
seconds. It is not in the catalog because the available artifact is an
unvalidated, zero-download GPU-oriented community conversion and Handy does
not yet have the exact Kaldi/Povey 80-bin feature extractor required by that
graph. A release implementation should be reproduced from the official NVIDIA
checkpoint, include the correct native preprocessor, and pass end-to-end NPU
accuracy tests.

### Nemotron Streaming, Canary, Granite Speech, and SenseVoice

No official OpenVINO GenAI ASR pipeline or Intel-validated NPU artifact was
found for these families in 2026.4. ONNX or Transformers availability alone is
not sufficient: RNNT/TDT, speech-LLM, and model-specific decoding each require
new native runtime work. Nemotron remains the most interesting future streaming
candidate, but it is not a safe incremental catalog addition today.

## Temporary artifacts

Conversion virtual environments, source checkpoints, generated model trees,
compiler probes, and NPU caches live under
`~/.cache/handy-openvino-build/`. They are not application dependencies and
must not be committed or included in the Debian package. Published model
weights live only in their Hugging Face repositories and download on demand.
